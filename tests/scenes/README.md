# Тестовые сцены

Маленькие сцены, написанные руками. Каждая проходит `validate.py --strict`, и каждая остаётся тестом навсегда.

| Файл | Что проверяет |
|---|---|
| `kub.json` | первый образец Никиты (куб 50 мм), как есть |
| `box_in_world.json` | коробка 100×50×20 с центром в (10, 20, 30), без поворота |
| `nested_boxes.json` | железная вставка 100×50×20 внутри бетонного блока 400×300×200, `parent`, без поворотов |
| `rotated_box.json` | коробка 20×40×70 в (300, −150, 80), поворот 90° вокруг z через углы Эйлера |
| `rotation_trap.json` | ловушка поворотов: три вложенные коробки, у двух поворот; если матрицу понять не так, маркер окажется не там |
| `box_rot30x_45z.json` | коробка 20×40×70 в (150, −60, 40), поворот 30° вокруг x, затем 45° вокруг z, углами Эйлера |
| `box_rot30x_45z_matrix.json` | та же коробка, тот же поворот, записанный матрицей (`matrix_active`, числа полностью) |

Ожидаемые значения в `verification` посчитаны вручную:

- `box_in_world`: объём 100·50·20 = 100 000 мм³, bbox = центр ± половины размеров.
- `nested_boxes`: bbox вставки дан в системе блока (родителя): центр (50, −30, 10) ± (50, 25, 10).
- `rotated_box`: поворот на 90° вокруг z переводит локальную ось x в мировую y, а y в −x, поэтому в мире размеры по x и y меняются местами: 40 × 20 × 70, bbox = (300, −150, 80) ± (20, 10, 35).
- `rotation_trap`:
  - R1 = Rz(90°)·Rx(90°) = [[0, 0, 1], [1, 0, 0], [0, 1, 0]]: ось x блока A смотрит вдоль мировой y, y — вдоль z, z — вдоль x. Поэтому bbox A = (100, 50, 0) ± (50, 150, 100).
  - B повёрнут Ry(90°), его длинная сторона 80 идёт вдоль z системы A: bbox B в системе A = (60, 0, 5) ± (15, 30, 40), то есть z от −35 до 45 при полувысоте A 50.
  - Маркер M в мире: p = R1·(R2·(30, 15, 0) + (60, 0, 5)) + (100, 50, 0) = **(75, 110, 15)**. Тест `tests/unit/test_rotation_scenes.py` считает это своими формулами и сверяет с планом и с `ExpectedChecks.hh`.
- `box_rot30x_45z`: R = Rz(45°)·Rx(30°) ≈ [[0.7071, −0.6124, 0.3536], [0.7071, 0.6124, −0.3536], [0, 0.5, 0.8660]]. Объём 56 000 мм³. bbox = центр ± |R|·(10, 20, 35) ≈ (150, −60, 40) ± (31.69, 31.69, 40.31), числа в файле округлены до 6 знаков.

Зачем нужны ловушка и коробка 30°/45°: при повороте ровно на 90° перепутанную матрицу (строки вместо столбцов) не видно. Транспонированная матрица Rz(90°) — это Rz(−90°), и коробка занимает то же место. Проверка: `tools/break_matrix.sh` (см. `docs/notes.md`).
