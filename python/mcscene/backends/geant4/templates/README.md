# Пакет шаблонов geant4

Здесь лежит весь текст, который генератор пишет для Geant4: C++, CMake и макросы. Python только готовит данные — числа, имена, порядок тел (`Geant4Backend.context()` в `backend.py`), а как это выглядит в файлах, решают шаблоны в этой папке. Почему Jinja2 и какие правила — в `docs/decisions/001-template-engine.md`.

| Файл | Что получается в проекте |
|---|---|
| `pack.json` | список: какие шаблоны печатать, какие файлы принадлежат пользователю, что скопировать как есть (`g4scene`) |
| `CMakeLists.txt.j2` | сборка: геометрия, стенд `check_geometry`, окно `scene_app` |
| `generated/GeneratedDetectorConstruction.cc.j2` | геометрия: материалы, мир, по функции на тело |
| `generated/GeneratedDetectorConstruction.hh.j2` | объявление класса геометрии |
| `generated/ExpectedChecks.hh.j2` | что стенд сверяет: объёмы и пробные точки |
| `harness/check_geometry.cc.j2` | стенд проверки |
| `app/main.cc.j2`, `app/vis.mac.j2`, `app/batch.mac.j2` | окно Geant4 с моделью |
| `user/DetectorConstruction.hh.j2` | файл пользователя: создаётся один раз, дальше не перезаписывается |
| `_common.j2` | шапка всех файлов (макрос) |
| `_solids.j2` | как каждая фигура записывается в C++ |

Каждый шаблон даёт файл проекта с тем же путём без `.j2`. Файлы с `_` в начале имени — общие куски, в проект они не попадают.

## Как читать шаблон

| Запись | Что значит |
|---|---|
| `{{ b.func }}` | вставить значение |
| `{{ b.volume\|cpp_str }}` | вставить через фильтр (`filters.py`): здесь — строка C++ в кавычках, `"Body"` |
| `{{ world.half_size\|map("mm")\|join(", ") }}` | каждое число через фильтр `mm` и через запятую: `352*mm, 165*mm, 165*mm` |
| `{% for b in bodies %} … {% endfor %}` | повторить для каждого тела |
| `{% if b.rotated %} … {% endif %}` | напечатать, только если условие верно |
| `{# … #}` | комментарий для читателя шаблона, в файл не попадает |

Строки, где стоят только `{% … %}` или `{# … #}`, в файл не попадают и пустых строк не оставляют.

## Что видят шаблоны

| Имя | Что это |
|---|---|
| `plan` | весь план генерации (`plan.py`, `G4Plan`): имя сцены, входной файл, sha256, версия |
| `world` | мир: материал, полуразмеры, где лежат тела, запас |
| `materials` | материалы: `id`, `nist`, `comment` |
| `bodies` | тела в порядке «родитель раньше ребёнка»: `func`, `volume`, `title`, `solid`, `material_id`, `mother`, `matrix`, `rotated`, `translation`, `probes` … |
| `solid_kinds` | какие виды фигур есть в сцене (для `#include`) |
| `colours` | цвета для `vis.mac`, уже посчитанные |

## Правила

1. **В шаблоне ничего не считаем.** Половины размеров, цвета, порядок — в Python, шаблон только печатает.
2. **Открывающая скобка C++ вплотную к вставке** пишется `{ {{- x }}`: просто `{{{` Jinja2 прочитала бы как начало вставки.
3. **После правки шаблона** — `pytest tests/golden`: тест покажет, что изменилось в каждой сцене. Если так и задумано — `UPDATE_GOLDEN=1 pytest tests/golden` и `git diff tests/golden` глазами перед коммитом.

Попробовать: поменять любой текст в комментарии `generated/GeneratedDetectorConstruction.cc.j2` → `pytest tests/golden` покажет изменение сразу во всех сценах → вернуть (`git checkout -- python/mcscene/backends/geant4/templates`).
