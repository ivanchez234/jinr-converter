# Контракт JSON между модулями: jinr-mc-scene v0.1

Этот пакет фиксирует, какой JSON выдаёт входной модуль (FreeCAD → JSON) и какой JSON принимает выходной модуль (JSON → Geant4 / FLUKA / MCNP). Если файл проходит `validate.py --strict`, выходной модуль обязан его принять. Если не проходит, значит ошибка либо в файле, либо в контракте, и тогда меняем контракт вместе, а не каждый у себя.

## Что в пакете

| Файл | Зачем |
|---|---|
| `КОНТРАКТ.md` | этот текст: правила человеческим языком |
| `schema/scene.schema.json` | те же правила в машинном виде (JSON Schema 2020-12). VS Code и PyCharm по ней подсказывают поля и подчёркивают ошибки |
| `validate.py` | проверка файла: структура, ссылки, повороты, объёмы, вложенность, меши. Нужен только Python 3.8+ (работает и в консоли FreeCAD) |
| `examples/` | пять правильных файлов, от одного куба до всех типов сразу |
| `bad/` | восемь неправильных файлов с типичными ошибками; на каждом валидатор должен падать |

```
python validate.py examples/*.json            # все пять: OK
python validate.py bad/*.json                 # все восемь: НЕ ПРОШЁЛ, с объяснением
python validate.py мой_экспорт.json --strict  # так проверять перед отправкой
```

Из FreeCAD:

```python
import sys; sys.path.append(r"/путь/к/jinr-mc-scene-v0.1")
import validate
validate.print_issues(validate.validate_file(r"/путь/scene.json", strict=True))
```

## 1. Главное: файл не бывает «мешем» или «примитивом»

Файл описывает всю сцену: список материалов и список тел. Представление выбирается **для каждого тела отдельно**, в поле `shape.type`:

| Ступень | `shape.type` | Когда | Пример |
|---|---|---|---|
| 1. Примитив | `box`, `cylinder`, `cone`, `sphere`, `torus` | объект FreeCAD — один параметрический примитив | бетонный блок, труба |
| 2. Булево дерево | `boolean` | Cut / Fuse / Common, у которых внизу только примитивы | стена с отверстием |
| 3. Меш | `mesh` | всё остальное: сплайны, скругления, PartDesign, импортированный STEP | ярмо магнита |

В одном файле спокойно лежат тела всех трёх видов (см. `examples/05_hall_all_types.json`). Внутри одного тела виды не смешиваются: меш не может быть операндом булевой операции. Если часть детали — примитив, а часть — сплайн, деталь лучше разрезать во FreeCAD на два тела.

Чем выше ступень, тем лучше. Примитивы и булевы деревья понимают все три программы. Меш понимает только Geant4: для FLUKA и MCNP такое тело будет ошибкой. Поэтому меш — запасной вариант, а не основной.

## 2. Общие правила

1. **Единицы**: длина в мм, углы в градусах, плотность в g/cm3. Блок `units` обязателен и в v0.1 других значений не допускает.
2. **Размеры полные**, не половинки: `size: [1000, 600, 400]` значит коробка 1000×600×400 мм. Делит на два генератор Geant4.
3. **Примитив центрирован в своей системе**. Коробка — в центре. Цилиндр, конус — в середине оси, ось = локальная z. У FreeCAD точка привязки другая (у `Part::Box` это угол, у `Part::Cylinder` и `Part::Cone` — центр основания), поэтому центр пересчитывается при экспорте (раздел 6).
4. **`transform`** — где центр тела в системе родителя (`translation`) и как оно повёрнуто (`rotation`). Поворот лучше всего писать матрицей (`matrix_active`) прямо из Placement: тогда с углами путаницы не будет вообще.
5. **Вложенность**. `parent` — `id` тела, внутри которого лежит это тело, или `null`, если оно лежит прямо в мире. Тело **целиком** внутри родителя, соседи с общим родителем **не пересекаются** (касаться можно). Если делать иерархию сложно, клади всё в мир (`parent: null`), но тогда никакие два тела не должны пересекаться. Вакуум внутри трубы — это отдельное тело-ребёнок трубы с материалом `vacuum`.
6. **Одно тело — один материал**.
7. **`id`**: латиница, цифры, `_` и `-`, первая буква не цифра, уникален во всём файле (и среди тел, и среди материалов). Брать из `Name` объекта FreeCAD (`Box001`), а не из `Label`: `Name` не меняется при переименовании. Русское имя — в `name`.
8. **`verification.cad_volume`** обязателен: это `Shape.Volume` из FreeCAD, объём собственной формы тела (детей не вычитать). По нему ловятся ошибки в размерах. `bbox` по желанию, но очень полезен: по нему ловится неправильный центр.
9. **Незнакомые поля не придумывать**. Всё, что нужно только тебе или для отладки, кладётся в `extras` (например `extras.freecad`). Генератор `extras` не читает.

## 3. Структура файла

```
{
  "format": "jinr-mc-scene",          всегда так
  "format_version": "0.1",
  "min_reader_version": "0.1",
  "source": { tool, tool_version, document },
  "units": { "length": "mm", "angle": "deg", "density": "g/cm3" },
  "extensions_used": [], "extensions_required": [],
  "world": { "material": "air", "margin_percent": 10 },
  "materials": [ ... ],
  "bodies": [ ... ]
}
```

**Материал** — либо NIST-имя Geant4, либо плотность и состав:

```json
{ "id": "concrete", "name": "Бетон", "nist": "G4_CONCRETE" }
{ "id": "steel_304", "name": "Сталь 304", "density": 7.93, "state": "solid",
  "composition": { "basis": "mass", "components": [
    { "element": "Fe", "fraction": 0.695 }, { "element": "Cr", "fraction": 0.19 },
    { "element": "Ni", "fraction": 0.095 }, { "element": "Mn", "fraction": 0.02 } ] } }
```

Доли в сумме дают 1. Подсказки для конкретных программ (имя материала FLUKA и т. п.) лежат в `extensions.JINR_target_hints`, это необязательно.

**Тело**:

```json
{ "id": "pipe", "name": "Ионопровод", "parent": null, "material": "steel_304",
  "transform": { "translation": [0, 0, 0],
                 "rotation": { "convention": "matrix_active",
                               "matrix": [[0, 0, 1], [0, 1, 0], [-1, 0, 0]] } },
  "shape": { "type": "cylinder", "radius": 60, "height": 4000 },
  "verification": { "cad_volume": 45238934.2, "bbox": [[-2000, -60, -60], [2000, 60, 60]] },
  "extras": { "freecad": { "name": "Cylinder001", "label": "Ионопровод", "type_id": "Part::Cylinder" } } }
```

Поворот можно записать тремя способами:

| `convention` | Поля | Когда |
|---|---|---|
| `identity` | нет | поворота нет |
| `matrix_active` | `matrix` 3×3 по строкам | **основной способ**: левый верхний блок 3×3 из `Placement.Rotation.toMatrix()`. Столбцы матрицы — оси тела в системе родителя |
| `euler_xyz_extrinsic_deg` | `angles: [a, b, c]` | для файлов, написанных руками: сначала поворот на a вокруг X, потом на b вокруг Y, потом на c вокруг Z (оси неподвижные), то есть R = Rz·Ry·Rx |

Отражения (det = −1) и масштабирование не допускаются.

## 4. Формы

| `type` | Поля (все длины полные, мм) | FreeCAD | Точка привязки FreeCAD → центр |
|---|---|---|---|
| `box` | `size: [x, y, z]` | `Part::Box`: Length, Width, Height | угол → сдвиг на (L/2, W/2, H/2) |
| `cylinder` | `radius`, `height`, необяз. `inner_radius` (труба) | `Part::Cylinder`: Radius, Height | центр основания → сдвиг на (0, 0, H/2) |
| `cone` | `radius_bottom`, `radius_top`, `height`, необяз. `inner_radius_bottom/top` | `Part::Cone`: Radius1 (низ), Radius2 (верх), Height | центр основания → (0, 0, H/2) |
| `sphere` | `radius`, необяз. `inner_radius` | `Part::Sphere` | уже центр |
| `torus` | `major_radius` (до оси трубки), `minor_radius` (трубка); ось — локальная z | `Part::Torus`: Radius1, Radius2 | уже центр |
| `boolean` | `op`: `union` / `subtract` / `intersect`, `left`, `right` | `Part::Fuse` / `Part::Cut` / `Part::Common` | см. ниже |
| `mesh` | `uri`, `encoding`, `sha256`, `n_facets`, `fallback_reason`, `tessellation`, `note` | что угодно | STL в локальной системе тела |

Неполные примитивы (Angle < 360 у цилиндра, конуса, тора, срезанная сфера) в v0.1 не описываются: такое тело пока идёт мешем с `fallback_reason: "PRIMITIVE_FIT_FAILED"` и пометкой в `note`. Сегменты по углу добавим в v0.2.

**Булево дерево**. `subtract` — это `left` минус `right` (у `Part::Cut` это Base минус Tool). Операнды — примитивы или вложенные `boolean`. У операнда может быть свой `transform`: где центр операнда в системе тела. Положение всего тела задаётся в `body.transform`, а у верхней формы тела своего `transform` нет. `Part::MultiFuse` и `MultiCommon` раскладываются в цепочку бинарных операций: `((a ∪ b) ∪ c)`.

```json
"shape": { "type": "boolean", "op": "subtract",
  "left":  { "type": "box", "size": [500, 3000, 2000] },
  "right": { "type": "cylinder", "radius": 100, "height": 600,
             "transform": { "translation": [0, 0, 0],
               "rotation": { "convention": "matrix_active", "matrix": [[0,0,1],[0,1,0],[-1,0,0]] } } } }
```

Отверстие лучше делать чуть длиннее стены (600 при толщине 500), чтобы не было совпадающих граней.

## 5. Как выбрать представление (это решает экспорт)

```
объект FreeCAD
├─ Part::Box / Cylinder / Cone / Sphere / Torus, полный (Angle = 360) → примитив
├─ Part::Cut / Fuse / Common / MultiFuse / MultiCommon,
│  и все операнды внизу проходят по этим же правилам               → boolean
└─ всё остальное                                                    → mesh + fallback_reason
```

`fallback_reason` — почему пришлось взять меш:

| Значение | Когда |
|---|---|
| `SPLINE_SURFACE` | есть сплайновые или иные непримитивные поверхности (скругления, лофты) |
| `PRIMITIVE_FIT_FAILED` | форма вроде простая, но в примитив не уложилась (неполный угол, PartDesign Pad из эскиза) |
| `BOOLEAN_TOO_COMPLEX` | булево дерево есть, но его не удалось выгрузить |
| `USER_FORCED` | пользователь сам попросил меш |

Позже можно научиться распознавать примитивы по топологии (PartDesign Pad из прямоугольника → `box`). Тогда меньше тел будет уходить в меш, а формат от этого не изменится.

## 6. Меш

- Замкнутая сетка без дыр, нормали наружу, двоичный STL (`stl-binary`) или текстовый (`stl-ascii`). Значение `encoding` должно совпадать с тем, что реально лежит в файле.
- Координаты в мм **в локальной системе тела**: STL пишется из формы со сброшенным Placement, а сам Placement уходит в `body.transform`. Если записать STL в глобальных координатах и вдобавок указать `transform`, тело уедет.
- `uri` — путь относительно JSON через `/`, например `meshes/Extrude001.stl`. Без `..` и абсолютных путей.
- `sha256` и `n_facets` должны соответствовать файлу. Так ловится ситуация «JSON новый, а STL старый».
- `tessellation` — параметры, с которыми делали сетку (`linear_deflection` в мм, `angular_deflection_deg`). По ним видно, насколько грубая сетка.
- `cad_volume` — объём B-rep (`Shape.Volume`), а не сетки. Валидатор сверяет их: расхождение больше 2% даёт предупреждение, больше 10% — ошибку.

## 7. Перевод из FreeCAD (набросок, проверить во FreeCAD)

Центр примитива в системе документа: `C = Placement.Base + R·c`, где `c` — смещение из таблицы раздела 4, а `R = Placement.Rotation`.

```python
import FreeCAD as App
def centre_and_matrix(obj):
    pl = obj.Placement                       # для вложенных объектов брать obj.getGlobalPlacement()
    if obj.TypeId == "Part::Box":
        c = App.Vector(obj.Length.Value/2, obj.Width.Value/2, obj.Height.Value/2)
    elif obj.TypeId in ("Part::Cylinder", "Part::Cone"):
        c = App.Vector(0, 0, obj.Height.Value/2)
    else:
        c = App.Vector(0, 0, 0)
    C = pl.Base + pl.Rotation.multVec(c)
    m = pl.Rotation.toMatrix()
    R = [[m.A11, m.A12, m.A13], [m.A21, m.A22, m.A23], [m.A31, m.A32, m.A33]]
    return [C.x, C.y, C.z], R
```

Для ребёнка `transform` записывается **относительно родителя**: `R_отн = R_родителяᵀ · R_ребёнка`, `t_отн = R_родителяᵀ · (C_ребёнка − C_родителя)`. Точно так же считается `transform` операнда булевой операции относительно системы тела.

Меш (тоже набросок): `s = obj.Shape.copy(); s.Placement = App.Placement()`, потом `MeshPart.meshFromShape(Shape=s, LinearDeflection=..., AngularDeflection=...)` и `.write("meshes/<Name>.stl")`, а `obj.Placement` уходит в `body.transform`.

## 8. Что проверяет validate.py

| Код | Что ловит | Типичная причина |
|---|---|---|
| E100 | неправильная структура: нет поля, неверный тип, неизвестный `type` | опечатка, забытое поле |
| W100 | неизвестное поле (в `--strict` это ошибка) | опечатка (`raduis`) или новое поле, не согласованное в контракте |
| E201–E206 | повторный `id`, ссылка на несуществующий материал или родителя, цикл, доли состава не дают 1 | переименовали объект, забыли материал |
| E210 | матрица не поворот (не ортонормирована или det = −1) | взяли матрицу с масштабом или зеркалом |
| E211 | `transform` у верхней формы тела | положение записали не туда |
| E212 | внутренний радиус ≥ внешнего, тор самопересекается | перепутали поля |
| E220 | объём по размерам ≠ `cad_volume`; подсказывает, если похоже на половинные размеры или диаметр вместо радиуса | **половинки вместо полных размеров** |
| W221 | оценка объёма булева дерева ≠ `cad_volume` | операнд не на месте |
| E230–E236 | меш: нет файла, не тот sha256, не то число граней, дыры, нормали внутрь, объём не тот | STL устарел или записан в глобальных координатах |
| E240 | форма не помещается в свой `bbox` | **угол или основание вместо центра** |
| E250 | ребёнок вылезает за родителя | то же, или неправильный `parent` |
| E251 | соседи пересекаются | реальное перекрытие в модели |

Геометрические проверки выборочные: проверяются точки на поверхностях, а не каждая точка тела. Ошибки они находят надёжно, но «OK» не доказывает отсутствие любых пересечений. Окончательно это проверит Geant4 (`CheckOverlaps`) на моей стороне.

## 9. Как меняем контракт

1. Схема — одна на двоих, лежит в общем репозитории. Своих «временных» полей в ядре не заводим, для этого есть `extras`.
2. Любое изменение = новая версия (`0.1` → `0.2`) + пример в `examples/` + строчка в таблице изменений внизу этого файла. Старые файлы при этом не ломаются: генератор переводит их в новую версию сам.
3. Перед отправкой файла: `validate.py --strict`. Лучше всего, чтобы экспорт запускал его сам в конце.
4. Каждый принятый файл от экспорта становится тестом. Если после изменений он перестал проходить или даёт другой результат, мы видим это сразу.

## 10. Порядок первых образцов

Не нужно сразу делать весь экспорт: шлём по одному образцу из настоящего FreeCAD.

1. Один `Part::Box`, стоящий не в начале координат. Проверяет единицы, полные размеры и центр.
2. `Part::Cylinder`, повёрнутый на 90°. Проверяет матрицу поворота и центр цилиндра.
3. Труба и вакуум внутри (`parent`). Проверяет иерархию и относительный transform.
4. `Part::Cut`: блок минус цилиндр. Проверяет булево дерево.
5. Деталь со скруглением. Проверяет меш.

Каждый образец проходит `validate.py`, а я прогоняю его через генератор и Geant4. Если какой-то пункт окажется неудобным для экспорта, меняем контракт на этом шаге, а не в конце проекта.

## 11. Не входит в v0.1 (будет позже по мере надобности)

Сегменты по углу (φ, θ), трапеции, многогранники и поликонусы, эллипсоиды, копии и массивы одного тела, изотопный состав, температура материала, параметры тесселяции на тело по запросу, `brep_uri` (B-rep рядом с мешем).
